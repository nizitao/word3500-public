# 操作逻辑梳理与优化说明

日期：2026-11-08　范围：仅前端导航与流转，不涉及接口与数据模型

---

## 一、优化前的操作地图

| 页面 | 现有入口（点击次数） | 主要动作 |
|---|---|---|
| `/` 单词表 | 登录后默认页 / 底部导航「单词」(1) | 分页、册/单元筛选、收藏、朗读、搜索 |
| `/learn` 单词浏览 | 首页工具栏「单词浏览」(1) | 选收藏夹 → 看词 → 开始测试 |
| `/favorites` 收藏夹 | 首页工具栏「收藏夹」(1)、中央面板「单词本」(2)、我 →「我的收藏夹」(2) | 建/改名/删夹、移出单词、连播、点词回首页 |
| `/quiz` 单词测试 | 中央面板「单词训练」(2)、房间「开始背」(2)、学习页「开始复习」(2)、`/learn` 底部按钮(2) | 三模式、单元背诵、断点续背 |
| `/study` 学习统计 | 底部导航「学习」(1) | 打卡、日历、掌握率、复习 |
| `/me` 我 | 底部导航「我」(1) | 账号、统计摘要、徽章、管理 |
| `/together` 一起背 | 中央凸起按钮 → 面板底部 (2) | 建/进房间、看成员进度 |
| `/search.html` 搜索 | 首页工具栏「搜索」(1) | 模糊/正则搜索 |

### 已确认的冗余与断点

1. **收藏夹没有一级入口**：属于高频功能，却要 1~2 次点击且分散在三处，用户找不到稳定入口。
2. **首页工具栏 3 个按钮与导航重复**：单词浏览 / 单词测试 / 收藏夹，与底部导航、中央面板指向同一目的地，同一功能两条路。
3. **收藏夹 → 测试绕路**：`/favorites` 只有「连播」和「点词回首页」，要测试必须再经 `/learn` 选一次收藏夹（3 步）。
4. **单元完成是死路**：完成页必须手动点「进入下一单元」；一个单元 55~101 词，连续背诵时每轮都被打断一次。
5. **页内「返回主页/返回」与底部导航重复**：`/favorites`、`/learn` 各有一个，和导航「单词」同目的地。
6. **「我」页重复列出一级入口**：我的收藏夹、单词训练。

## 二、重构后统一的交互规则

1. **一级入口只有 5 个**：单词 / 收藏 / 一起背（凸起）/ 学习 / 我。其余页面只能由一级入口或上下文进入（中央面板、房间、复习队列、收藏夹详情）。
2. **页面内不再放"回到某个一级页"的出口**，只保留页内层级回退（如收藏夹详情的「所有收藏夹」）。
3. **完成态必须有下一步**：能自动流转的自动流转（倒计时 + 可取消），不能自动的给一个明确主按钮。
4. **进入练习的合法路径收敛为 4 条**：收藏夹详情「开始测试」/ 中央面板「单词训练」/ 房间「开始背这份词表」/ 学习页「开始复习」。

原来两页各有一份收藏夹列表：`/favorites` 管夹（建/改名/删/移出/连读），`/learn` 管看（筛选/统计/搜索/测试）。
现在 `/favorites` 一个页面两个视图：

| 视图 | 内容 |
|---|---|
| 文件夹视图 | 「全部单词」伪卡片（5093 词）+ 各收藏夹 + 新建 |

### 2. 首页内联搜索（子 Agent 执行）

工具栏「搜索」按钮 → 内联输入框（防抖 250ms），就地出结果、就地恢复；隐藏词表与分页，避免"能点但没意义"的按钮。

### 3. 顺手修掉的一个真实 bug

`/quiz` 无 cid 进入时，`init()` 会先 `refreshQuiz()` 出随机 10 题，再被单元面板的 `selectUnit()` 覆盖 —— 用户会先闪一下随机题，且「当前词库」提示被冲掉。
改为：单元模式只让 `initUnitPanel()` 出题，随机模式先出题、面板只填下拉；词库无分册信息时再兜底补随机题。

## 六、兼容性与风险


- **路由不变**：`/favorites`、`/learn`、`/quiz`、`/together` 都保留，书签、房间邀请链接 `?code=`、`/quiz?book=&unit=` 深链均不受影响。
- **功能只移入口不删能力**：被移除的都是重复入口，目的地仍可从一级入口或上下文到达。
- **quiz.js 影响面**：仅完成态渲染与定时器，未触碰三模式会话、选项缓存、反作弊、断点数据结构。
- **回滚**：功能改动集中在 8 个前端文件（另有 5 个页面只改了 `nav.js?v=` 缓存号），`git checkout` 对应文件即可；无数据库迁移。

## 七、第三轮（2026-11-14）：接口契约、默认口令、完成页出口

### 1. 安全：移除接口层缺省口令（CVE 分析先行）

| 项 | 结论 |
|---|---|
| 漏洞位置 | `POST /api/auth/users` 的 `create` 与 `reset_password`：`body.get("password", "admin123")` / `body.get("new_password", "admin123")` |
| 分类 | 本项目无公开 CVE；按 CWE 归类为 **CWE-1188 不安全的缺省初始化**，兼有 **CWE-798 硬编码凭据 / CWE-1392 使用默认凭据** 特征 |
| 触发条件 | 调用方持有 `admin:users` 权限（管理员 token、或借管理员会话的 CSRF/脚本调用），且省略密码字段 |
| 影响 | 静默创建/重置出「口令写在 README 里」的账号；前端 `admin.js` 有必填校验，但接口层可被绕过，属校验只做在客户端 |
| 严重度 | 中（需管理员权限），但修复成本为零 |
| 修复 | 两处改为**强制传参**：非字符串或空值直接 400 `bad_request`；`admin.js` 本来就强制传密码，无兼容影响 |
| 后续加固 | 首次启动管理员口令也已改为随机生成，写入 `data/initial_admin_password.txt`（权限 600），不再使用 `admin123`；详见根目录 README |

### 2. 「全部单词」补齐音标

`/api/words/all` 默认仍是 `[id, word, meaning]` 三元紧凑数组（`search.js` 的 WordStore 按下标取词，不能动）。
新增 `?full=1` → `[id, word, pronunciation, meaning]`，两份独立缓存互不污染；`favorites.html` 的全部单词视图改用 `full=1`，并兼容 3/4 元数组。
→ 原先全部单词卡片没有音标，现在与首页表格一致。

### 3. 随机 10 题完成页不再是单出口

`renderResult()` 保留「再来一轮」，补「返回收藏夹」；复习队列来源（`?review=1`）显示「返回学习」→ `/study`。不做自动跳转（来源多样，自动跳反而可能跳错）。
